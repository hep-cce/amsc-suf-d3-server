## Findings

The `libtorchtrt_runtime.so` failure was caused by mixing two incompatible
LibTorch installations in the Triton server process:

- The Triton 26.05 PyTorch backend includes its own NVIDIA-patched LibTorch in
  `/opt/tritonserver/backends/pytorch`. The backend libraries use `$ORIGIN` as
  their runpath so that they load this copy.
- The Dockerfile also installs the upstream `torch==2.12.0` wheel and previously
  put `/opt/torch/lib` first in the global `LD_LIBRARY_PATH`.
- The Dockerfile globally preloaded the PyG extension libraries. This caused the
  wheel's LibTorch libraries to enter the Triton server process before the
  PyTorch backend was loaded.
- The undefined `torch::Library::def` symbol is present in Triton's bundled
  `libtorch_cpu.so`, but absent from the upstream wheel's `libtorch_cpu.so`.
  `ldd` confirmed that the failing image resolved `libtorchtrt_runtime.so`
  against `/opt/torch/lib` rather than the backend directory.

This is an ABI mismatch even though both installations report a PyTorch 2.12
version. The Triton PyTorch backend documentation notes that it requires a
[specially patched PyTorch build](https://github.com/triton-inference-server/pytorch_backend#build-the-pytorch-backend-with-custom-pytorch).

## Fix

The Dockerfile now:

- leaves the pip wheel's LibTorch directory out of global `LD_LIBRARY_PATH`,
  allowing Triton's PyTorch backend to use its bundled libraries; and
- no longer sets a global `LD_PRELOAD` for the PyG extensions. Python model
  processes can import the wheel and PyG extensions through their own runpaths.

The three affected ParticleNet TorchScript models only use built-in `aten` and
`prim` operators, so they do not require the removed PyG preload.

## Validation

The existing image was run with environment overrides equivalent to the
Dockerfile fix. The following models all initialized successfully and reached
`READY`:

- `particlenet_PT`
- `particlenet_AK8_MD-2prong_PT`
- `particlenet_AK8_MassRegression_PT`

The smoke test was performed on a login node without a GPU, so it verifies model
loading and removal of the ABI error, but not GPU inference. Imports of PyTorch,
`torch_scatter`, `torch_sparse`, `torch_cluster`, and `torch_spline_conv` also
succeeded without the global preload.

   LibTorch:

   ```bash

     'ldd /opt/tritonserver/backends/pytorch/libtorchtrt_runtime.so | grep libtorch_cpu'
   ```

   `/opt/tritonserver/backends/pytorch/libtorch_cpu.so`, not
   `/opt/torch/lib/libtorch_cpu.so`.
